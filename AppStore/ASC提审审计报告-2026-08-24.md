### P0-1 🔴 线上官网 / 隐私政策 / 条款页仍在宣传「iCloud 同步健康数据」

**这是本次审计发现的最严重问题。**

App 内的 CloudKit 已按 Guideline 5.1.3(ii) 完全移除（代码层面已核实干净），但**填进 App Store Connect 的三个公开 URL，线上实际内容仍是旧版**，仍然描述这个功能存在。


GitHub Pages 从 `main` 分支的 `docs/` 目录发布，因此线上仍在服务 `9207cf7` 那一版。本地已修好的版本对审核员**完全不可见**。

#### 触发的审核条款（三条同时踩）

1. **Guideline 5.1.3(ii)** —— 你的隐私政策正在**主动声明**把个人健康数据存入 iCloud/CloudKit。这正是上一轮被拒的原因；审核员会读这个 URL。
2. **Guideline 2.3.1（准确的元数据）** —— 官网把一个 app 里根本不存在的功能列为免费档卖点。
3. **Guideline 5.1.1** —— 隐私政策与 app 实际数据行为不一致。

**方案 A（推荐）：提交并推送已改好的 `docs/`**

优点：一次到位，三个 URL 全部修正，无需改动 ASC 后台任何字段。

### P2-1 🟡 出口合规声明建议留存书面依据

`ITSAppUsesNonExemptEncryption = false`，而 app 确实使用了加密：`EncryptedBackupEngine.swift` 采用 **AES-GCM（CryptoKit）+ PBKDF2-HMAC-SHA256（CommonCrypto，最低 210,000 轮）**。

**判断：声明为 `false` 是成立的** —— 使用的是 Apple 操作系统自带的标准算法，且仅用于保护用户自己的数据，符合豁免条件。无需改动。

建议仅将上述认定理由归档一份，以备将来年度自查或抽查时引用。

### P2-2 🟡 主 app 隐私清单存在一项多余声明

`Resources/PrivacyInfo.xcprivacy` 声明了 `NSPrivacyAccessedAPICategoryFileTimestamp`（理由 `3B52.1`）。全量扫描后，代码中唯一相关调用是：

```
Sources/Support/BackupTransfer.swift:77
url.resourceValues(forKeys: [.isRegularFileKey, .fileSizeKey])
```

`.isRegularFileKey` 与 `.fileSizeKey` 均**不属于** Apple 的 File Timestamp 必要理由 API 清单。属于**多声明**。

**多声明不会导致拒审**，无需处理。若追求整洁可在下个版本移除。

### P2-3 🟡 截图未确认取自 build 7
