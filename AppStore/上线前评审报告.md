## 🔴 P0 — 已修复:CloudKit 模型不兼容(会崩溃 / 静默丢数据)

**问题**:SwiftData + CloudKit 硬性要求「所有非可选属性必须可选或带默认值」。5 个模型共 **27 个非可选属性都没有默认值**。开启 iCloud 同步时,`ModelContainer` 创建失败(CoreData 错误 **134060**),而 `VelaApp` 用 `try?` 兜底 → **静默降级为仅内存模式(丢失全部持久化)**,极端情况 `try!` 兜底还会崩。

**为什么没被发现**:`CloudSync.makeConfiguration` 在「未登录 iCloud / 无 entitlement」时总回落本地。开发机/模拟器没登录 iCloud,所以**CloudKit 这条路径从来没真正跑过**,提交信息写「接通 CloudKit」但实际未验证。

**证据**:我用临时诊断 `--force-cloudkit` 强制走 CloudKit 配置,日志明确报:
> `CloudKit integration requires that all attributes be optional, or have a default value set` — 后附全部 27 个属性名。

**修复**:给 5 个模型全部非可选属性加默认值(`init` 仍覆盖,行为不变)。⚠️ 注意 `@Model` 宏要求默认值**完全限定**(`Date.now` 不能写 `.now`,否则编译报错)。

**验证**:同一诊断从 `FAILED / 134060` → **`container OK`**;本地模式冒烟测试正常(15 经期 + 14 每日记录持久化)。已提交 `46daca2`。

## ⚠️ 已知限制(非阻断,建议知悉)

1. ~~CloudKit 多端重复记录~~ **已解决**:codex 加了 `DedupSweep`(启动折叠同 dayKey/key,DailyLog 做字段级合并+症状并集,不丢数据)。我用 `--seed-dups` 实测:注入 2 条重复 → 启动后 DB 回到 15/14 无重复,验证通过。
2. **切换 iCloud 开关需重启 app**:`ModelContainer` 启动时按当时配置创建一次。设置页已有提示,可接受。
3. **`try!` 内存兜底并非绝对安全**:两个配置都失败时,最后的 `try!` 可能崩。P0 修复后正常路径不会触发,但严谨起见可改为「显示错误页」而非 `try!`。优先级低。
