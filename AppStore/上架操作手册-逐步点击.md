# Maren 上架操作手册(逐步点击版)

> 三大阶段,按顺序做:**A. Xcode 配置签名 + 打包上传** → **B. 网页 App Store Connect 填资料 + 建内购** → **C. 上传审核前终检**。
> 前提:已加入 Apple Developer Program($99/年,已交)。
>
> ⚠️ **2026-08-14 起不再有「CloudKit 阶段」**:健康数据纯本地、不接 iCloud/CloudKit(App Review Guideline 5.1.3(ii))。
> 旧版的阶段 C「CloudKit Dashboard 部署」已删除,不要按旧文档去开 iCloud capability 或部署 schema。

---

# 阶段 A · Xcode(签名 + 能力 + 打包上传)

## A1. 填开发者 Team(3 个 target 都要)
1. 打开 `Vela.xcodeproj`(左上角项目名)。
2. 左侧文件树最顶点蓝色工程图标「Vela」→ 中间面板 TARGETS 列表选 **Vela**。
3. 顶部标签点 **「Signing & Capabilities」**。
4. 勾选 **「Automatically manage signing」**。
5. **Team** 下拉 → 选你的 Apple Developer 账号(个人名或公司名)。
6. 对 **VelaWidgetExtension**、**VelaWatch** 两个 target **重复 3–5 步**(各自设一遍 Team)。
   - 设完 Team 后,Xcode 会自动去开发者门户注册这三个 Bundle ID(`cd.cc.vela` / `.widget` / `.watchkitapp`)。

## A2. 确认能力(capability)都在
在 Vela target 的「Signing & Capabilities」页,应能看到这几块(entitlements 里已配好,Xcode 会自动开):
- **App Groups**:`group.cd.cc.vela`(勾上)。
- **HealthKit**:应已列出(若没有,点左上「+ Capability」搜 HealthKit 加上)。
- ❗ **不要**勾 iCloud / CloudKit:app 不再包含 iCloud entitlement。若之前在旧版手册指引下勾过,请在这里移除,并到开发者门户确认 App ID 的 iCloud capability 也未勾选。
- ⚠️ 若某个能力报红(provisioning 错误):点报错行右侧 **「Try Again」**,或 Xcode → Settings → Accounts → 选账号 → **「Download Manual Profiles」**。

## A3. 确认版本号
1. Vela target → **「General」** 标签 → **Identity** 区。
2. **Version** 应为 `1.0.0`(已在 `project.yml` 的 `MARKETING_VERSION` 设好),**Build** 为 `2`(**2026-08-14 已由 1 升到 2**,因为移除了 CloudKit 并补了本地化,必须用比已上传过的更高的 build 号)。
   - 改版本号直接改 `project.yml` 后跑 `xcodegen generate`,三个 target 自动跟随。

## A4. 打包(Archive)
1. Xcode 顶部中间的**设备选择器**(在 ▶️ 运行键右边)→ 选 **「Any iOS Device (arm64)」**。
   - ⚠️ 必须是真机目标,**不能是模拟器**,否则 Archive 菜单是灰的。
2. 顶部菜单 **Product → Archive**。等几分钟,完成后自动弹出 **Organizer** 窗口。
   - 若 Archive 灰色:确认第 1 步选的是「Any iOS Device」。
   - StoreKit 本地测试文件(Maren.storekit)只在「运行」用,**Archive 走 Release,不受影响**,不用管。

## A5. 上传到 App Store Connect
1. Organizer 里选中刚生成的 archive → 右侧蓝色 **「Distribute App」**。
2. 选 **「App Store Connect」** → Next。
3. 选 **「Upload」** → Next。
4. 后面几屏(签名、符号表)全部默认 → **Next → Upload**。
5. 传完等 15–60 分钟(Apple 后台处理 build)。可在网页 ASC 的 TestFlight 页看到「Processing」。

> ⚠️ 若这是**第一次上传**,ASC 里得先有 App 记录(见阶段 B1)才能关联;可以先做 B1 再回来传,或先传、build 处理完后在版本页选它。

# 阶段 B · App Store Connect 网页(appstoreconnect.apple.com)

登录 **appstoreconnect.apple.com**。

## B1. 新建 App
1. 首页点 **「Apps」** → 左上蓝色 **「+」** → **「New App」**。
2. 弹窗填:
   - **Platforms**:勾 iOS
   - **Name**:`Maren: Period & Mood`
   - **Primary Language**:English (U.S.)
   - **Bundle ID**:下拉选 **`cd.cc.vela`**(阶段 A 设完 Team 后会出现在这里;没有就说明 A1 没成功)
   - **SKU**:`maren-ios-001`
   - **User Access**:Full Access
3. 点 **「Create」**。

## B2. App 信息(左栏 General → App Information)
- **Subtitle**:`Private period & mood tracker`
- **Category → Primary**:Health & Fitness;**Secondary**:Medical(或留空)
- **Content Rights**:勾「Does not contain, show, or access third-party content」
- **Age Rating** → 点 **「Edit」** → 逐题答:
  - Medical/Treatment Information → **None**
  - 其余(暴力/性/赌博等)→ 全 **None**
  - Unrestricted Web Access → **No**
  - → 结果约 **12+**,点 Done。
- **Privacy Policy URL**:填你把 `AppStore/privacy-policy.md` 托管后的网址(见文末「托管隐私政策」)。

## B3. App 隐私问卷(左栏 General → App Privacy)

> ✅ **结论(2026-08-14 更新):选 `No, we do not collect data from this app`。**
> 健康数据只在本机 SwiftData(无 iCloud/CloudKit、无网络层、无分析 SDK、无第三方);HealthKit 数据仅在你设备上使用、不用于追踪;内购由 Apple 处理。已按旧写法勾过 Health & Fitness 的,回 App Privacy → Edit 取消勾选并改为 No → Save → **Publish**。

1. 点 **「Get Started」**(或 Edit)。
2. 问题「Do you or your third-party partners collect data from this app?」→ 选 **「No, we do not collect data from this app」** → Save → **Publish**。

## B4. 建内购 —— 订阅(月 + 年)
左栏 **Monetization → Subscriptions**:
1. **Subscription Groups** → **「Create」** → Reference Name 填 `Maren Premium` → Create。
2. 进入该组 → **「Create Subscription」**:
   - **年订阅**:Reference Name `Maren Premium Yearly`,Product ID **`cd.cc.vela.premium.yearly`**,Duration **1 Year** → Create。
     - **Subscription Prices** → 「Add Subscription Price」→ 选 **USD 29.99** → 确认。
     - **Localizations** → 「+」加 English:Display Name `Yearly`,Description `Maren Premium, billed yearly. Best value.`(可再加中文)。
   - 再 **「Create Subscription」** → **月订阅**:`cd.cc.vela.premium.monthly`,Duration **1 Month**,价格 **USD 3.99**,Display Name `Monthly`。
3. 每个订阅:**App Store Promotion / Review Information** 区上传一张审核截图(用 `AppStore/screenshots` 里的付费墙图)。

## B5. 建内购 —— 买断(终身,Non-Consumable)
左栏 **Monetization → In-App Purchases**:
1. **「Create」** → 类型选 **「Non-Consumable」**(⚠️ 不是订阅!)。
2. Reference Name `Maren Premium Lifetime`,Product ID **`cd.cc.vela.premium.lifetime`** → Create。
3. **Price** → 选 **USD 69.99**。
4. **Localization** → 加 English:Display Name `Lifetime`,Description `Maren Premium forever. One-time payment.`
5. **App Store Review Screenshot**:上传付费墙截图;Review Notes 填:`All Premium features unlock via any one product. Restores via "Restore Purchases". No login.`

## B6. 版本页填元数据(左栏选 iOS App 下的 **「1.0 Prepare for Submission」**)
- **Screenshots**:把 `AppStore/screenshots/iphone_1284x2778/` 里的 1–5 张**拖进** 6.9"/6.5" iPhone 区;把 `watch_410x502/1_watch_glance.png` 拖进 Apple Watch 区。
- **Promotional Text**:清单里那段(可随时改)。
- **Description**:复制 `ASC-上架填写清单.md` 里的「Description 全文」。
- **Keywords**:`period tracker,cycle,menstrual,PCOS,ovulation,mood,symptom,privacy,irregular,calendar,pms,fertility`
- **Support URL**:一个能联系你的网页(可以是带邮箱的简单页,或 GitHub 仓库页)。
- **Build**:向下滚到 **「Build」** 区 → 点 **「+」** 或 **「Add Build」** → 选阶段 A5 传上来、已处理完的 build(没出现就是还在 Processing,等)。
- **In-App Purchases and Subscriptions**(版本页里的这一区):**首次提交必须把 3 个内购勾上一起提交**,否则内购不过审。
- **App Review Information**:
  - Sign-in required:**No**
  - Contact:你的名字 / 电话 / 邮箱(billy.yu@me.com)
  - Notes:`No account needed; all data stored locally on-device (no iCloud, no CloudKit). Insights appear after logging a couple of cycles. Apple Health is optional and off by default.`
- **Version Release**:选「Automatically release」或「Manually release」。

## B7. 提交
- 版本页右上角蓝色 **「Add for Review」→「Submit for Review」**。
- 出口合规:因为已在 Info.plist 设 `ITSAppUsesNonExemptEncryption=NO`,**不会再弹出口加密问卷**,直接过。

# 阶段 C · 上传审核前终检(替代原 CloudKit 阶段)

> ⚠️ **原「CloudKit Dashboard 部署 schema 到生产」阶段已废弃(2026-08-14)**。app 不再使用 CloudKit,
> 没有 schema、没有容器、没有 Production 环境需要部署,真机上也不应显示 iCloud 同步入口;请忽略任何旧文档中的 CloudKit 步骤。

1. 确认 `project.yml` 里 **没有** iCloud entitlement、`Vela.entitlements` 里只有 App Groups + HealthKit。
2. 确认 Vela target **「Signing & Capabilities」** 没有 iCloud / CloudKit(若有,移除)。
3. 开发者门户确认 App ID `cd.cc.vela` 的 Capabilities **不勾 iCloud**。
4. Archive → Distribute → Upload 前,按 `03-Resubmission-Audit-and-Checklist-ZH.md` 走一遍终检表。

# 附:托管隐私政策(ASC 要填 URL)

最简单免费方式(GitHub Pages):
1. 建个公开 GitHub 仓库(如 `maren-legal`)。
2. 把 `AppStore/privacy-policy.md` 传上去,重命名为 `index.md`(或 `README.md`)。
3. 仓库 **Settings → Pages** → Source 选 `main` 分支 `/root` → Save。
4. 等 1 分钟,得到网址 `https://<你的用户名>.github.io/maren-legal/` → 填进 B2 的 Privacy Policy URL。

# 提交后
- 审核一般 **24–48 小时**。被拒会在 ASC 的「Resolution Center」给原因,改完重交即可。
- 常见健康类追问:确认文案无避孕宣称(已合规)、隐私政策可访问(已备)、内购能恢复(已备「恢复购买」)。
