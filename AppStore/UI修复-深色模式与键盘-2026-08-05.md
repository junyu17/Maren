## B-1(P1)· 深色模式下日历的阶段颜色几乎看不出来

### 现象(已复现)
深色模式打开日历,除了「预计开始区间」的**虚线圈**能一眼看到,卵泡期 / 排卵期 / 黄体期三种阶段色几乎糊成同一块黑;图例上的小圆点同样分辨不出。浅色模式下正常。

### 根因
`Sources/Support/CyclePhase.swift` 里阶段色是**一套固定 sRGB 值 + 固定透明度**:

```swift
case .follicular: return Color(red: 0.34, green: 0.70, blue: 0.62)   // 墨绿
var fillOpacity: Double { self == .ovulatory ? 0.42 : 0.22 }
```

透明色是要跟**背景**做合成的:
- 浅色模式背景是白 → 0.22 的墨绿合成出来是 `(0.86, 0.93, 0.92)` 的淡雅浅绿,正好。
- 深色模式背景是纯黑 → 同样的 0.22 合成出来是 `(0.075, 0.154, 0.136)`,亮度只有 0.13,**基本就是黑**。排卵期的深紫(0.38, 0.26, 0.74)本身亮度就低,压得更黑。

而虚线圈用的是 `strokeBorder` 的**不透明**描边色,所以只有它清清楚楚 —— 和 Billy 描述的完全一致。

一句话:**深色模式不能靠调透明度救,必须另给一套更亮、更饱和的色值。**

### 改法
`CyclePhase` 改成浅色 / 深色两套 RGB,用 `UIColor(dynamicProvider:)` 包成动态色,随系统外观自动切换;并把「日历格填充」和「图例圆点」拆成两个语义化属性:

| 属性 | 用途 | 浅色 alpha | 深色 alpha |
|---|---|---|---|
| `tint` | 阶段主色(不透明) | 1.0 | 1.0 |
| `cellFill` | 日历格背景 | 0.22 / 排卵期 0.42 | 0.42 / 排卵期 0.55 |
| `legendFill` | 图例、说明页小圆点 | 0.50 | 0.85 |

深色那套 RGB(整体提亮 + 提饱和):

| 阶段 | 浅色 | 深色 |
|---|---|---|
| 经期 | (0.90, 0.40, 0.46) | (0.98, 0.55, 0.60) |
| 卵泡期 | (0.34, 0.70, 0.62) | (0.44, 0.88, 0.78) |
| 排卵期 | (0.38, 0.26, 0.74) | (0.66, 0.56, 1.00) |
| 黄体期 | (0.95, 0.66, 0.36) | (1.00, 0.76, 0.44) |

**浅色模式的色值与透明度一字未动** —— 这是刻意的:App Store 截图是浅色模式拍的,改浅色就等于截图作废。

改动文件:
- `Sources/Support/CyclePhase.swift`(新增 `rgbPair` / `cellFill` / `legendFill`,删掉 `fillOpacity`)
- `Sources/Views/CalendarView.swift`(日历格 + 图例两处)
- `Sources/Views/PhaseInfoView.swift`(说明页圆点)

### 复验
模拟器 iPhone 17 Pro,同一份 demo 数据(`--seed-demo`),2026 年 7 月:
- **深色**:12–22 卵泡期青绿、23–25 排卵期紫、26–31 黄体期琥珀,三段一眼分得开;白色日期数字在三种填充上都清晰。
- **浅色**:与修改前逐像素一致(截图无需重拍)。

## B-2(P1)· 每日记录页输入备注后,键盘收不掉 + 底部 4 个标签消失

### 现象(已复现)
「今天」页最下面的**备注**输入框打字后:
1. 键盘收不掉;
2. 屏幕底部的 4 个标签(日历/今天/趋势/设置)不见了。

### 根因(两条其实是同一个)
`Sources/Views/DailyLogView.swift` 的备注是多行输入:

```swift
TextField("想记点什么…", text: $note, axis: .vertical)
```

`axis: .vertical` 的输入框,**回车键是换行,不是「完成」**,所以键盘上没有任何收起入口。同时:
- 页面没有 `@FocusState`,点「保存今天的记录」只是执行了 `save()`,**没有 resign 第一响应者** → 键盘原地不动。
- 页面也没有键盘工具条,点别处在 Form 里也不会收键盘。

而 **iOS 在键盘弹起时会自动把底部浮动标签栏一起隐藏**(系统行为)。键盘既然收不掉,标签栏就一直不回来 —— 所以「4 个选择没有了」其实是「键盘没收掉」的结果,不是标签栏自己丢了。

还有个连带问题:键盘弹起时「保存」按钮被压到键盘下面,够不着。

### 改法
`Sources/Views/DailyLogView.swift`:
1. 加 `@FocusState private var noteFocused: Bool`,绑到备注 `TextField`;
2. 加键盘工具条,右侧一个**「完成」**按钮 → `noteFocused = false`;
3. `save()` **第一行**就 `noteFocused = false`(点保存自动收键盘,标签栏立刻回来);
4. 显式 `.scrollDismissesKeyboard(.interactively)` —— 往下拖也能收键盘,不必非得点「完成」。

`完成` 这个 key 目录里已有英文 `Done`,无需补翻译。

### 复验
模拟器输入备注 → 键盘工具条出现「完成」→ 点「保存今天的记录」→ 焦点释放、工具条消失、**底部 4 个标签立刻恢复**;备注内容正常落库。

## B-3(产品问题)· 自定义追踪项(custom trackers)加了之后有什么用?

**不是 bug,是「价值没被看见」。** 代码里它确实有用,链路是通的:

| 加完之后它出现在哪 | 代码位置 | 是否免费 |
|---|---|---|
| 「今天」页症状区多一个可点的胶囊标签,能像内置症状一样打勾 | `DailyLogView.ChipGrid` | ✅ 免费 |
| 「趋势」页 →「症状频次」条形图,和内置症状一起排名 | `TrendsView.symptomFrequency` | 🔒 Pro |
| 「趋势」页洞察,例如「你的『XX』常在黄体期升高」 | `InsightEngine.symptomPhaseInsights` | 🔒 Pro |
| CSV / PDF 导出:每日记录里写显示名,另出一份 `Maren-自定义症状.csv` 存 key→名字映射 | `DataExport` | ✅ 免费 |

**所以你的感受是准的**:免费用户加完自定义项,除了多一个能点的标签,**看不到任何回报** —— 两处真正的价值(频次图、阶段洞察)都在付费墙后面。管理页(设置 → 自定义追踪项)也只列了名字,没说加了能干嘛。

## B-4 · 「今天」页症状区排序(Billy 指定)

### 改前
`ChipGrid` 把**内置 + 自定义混在一起按标签长度升序**重排,「＋ 自定义」按钮固定在第一个。后果:每加一个自定义项,内置项就整体挪位,用户靠肌肉记忆点「痛经」「疲惫」会失效。

### 改后(按你要求)
固定三段,互不干扰:

```
[内置症状 —— Symptoms.all 的定义顺序,永不重排]
[＋ 自定义 按钮]
[用户自定义项 —— 按创建时间]
```

「＋」从第一位挪到内置项之后:它是低频动作,不该占第一个位置。

### 复验
模拟器:内置 14 项按原顺序(痛经→头痛→腹胀→…→脱发→多毛)→「＋ 自定义」→ 新建的 `📝 Water`(新建即选中)。加自定义项前后,内置项位置完全没动。

## B-5 · 命名统一:「追踪项 / trackers」(Billy 2026-08-05 选 B —— 要有竞争力)

### 为什么改
歧义的证据不是措辞,是新建页自己的提示:**「例如:偏头痛、拉伸、喝水」** —— 拉伸和喝水不是症状,app 在主动邀请用户往一个叫「症状 / Symptoms」的区里塞非症状的东西。同一个概念还有三个名字:区标题「症状」、按钮「自定义」、设置项「自定义追踪项」,导出文件又叫 `Maren-自定义症状.csv`。

选 B = 把伞形词升成**追踪项 / trackers**:内置的仍叫「症状」,聚合两者的地方一律叫「追踪项」。这样「什么都能记」成为可宣称的差异点,而不是一个藏在设置里的隐藏功能。

### 改了什么(全量)

| 「趋势」卡片 ×2 | 症状频次 / Symptom frequency | 追踪项频次 / Tracker frequency |
| 「趋势」空状态 | 还没有症状记录。 | 还没有追踪项记录。 |
