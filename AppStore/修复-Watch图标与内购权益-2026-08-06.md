## C-1(P0)· Archive 上传报 90391 / 90713

### 报错原文
```
90391  Missing Icons. No icons found for watch application 'Vela.app/Watch/VelaWatch.app'.
90713  Missing Info.plist value. A value for the Info.plist key 'CFBundleIconName'
       is missing in the bundle 'cd.cc.vela.watchkitapp'.
```

### 根因
**Watch app 完全没有自己的 asset catalog。**

`project.yml` 里 VelaWatch 的 sources 是 `WatchSources` + `Shared` + `Resources/Localizable.xcstrings` —— 唯一的资源目录 `Resources/Assets.xcassets` 只在主 app target 里。而且就算把它加进 Watch target 也没用:里面 `AppIcon.appiconset/Contents.json` 写的是

```json
{ "idiom" : "universal", "platform" : "ios", "size" : "1024x1024" }
```

`platform: ios` —— 编译 watchOS 时不会为它生成任何图标。

**为什么真机能跑、一上传就挂**:Debug 构建根本不校验 App Store 的图标规则;这两条只在 Archive 验证/上传阶段检查。所以「能编译」和「能上传」在这件事上没有相关性。

### 改法
1. 新增 `WatchSources/Assets.xcassets/AppIcon.appiconset/`,`Contents.json` 里 **`"platform" : "watchos"`**,图片复用主 app 那张 1024×1024(已确认无 alpha 通道 —— 带 alpha 的图标 Apple 也会拒)。因为 `WatchSources` 本来就是 Watch target 的 source path,XcodeGen 自动收进去,不用改 sources。
2. `project.yml` 的 VelaWatch 加 **`ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon`**。该 target 是 `GENERATE_INFOPLIST_FILE: YES`,Xcode 会据此自动注入 `CFBundleIconName`。

### 验证(构建产物,不是看代码)
```
Watch Info.plist:  CFBundleIcons → CFBundlePrimaryIcon → CFBundleIconName = "AppIcon"   ← 治 90713
Watch Assets.car:  AppIcon  idiom=watch  1024x1024                                       ← 治 90391
```

> 改了 `project.yml` 之后必须重跑 `xcodegen generate` 再 Archive,否则 `.xcodeproj` 里没有这个设置。

## C-2(P0)· 沙盒购买显示成功,但功能不解锁 / 恢复购买说没有

### 现象演进
1. 最初:点订阅 → Apple 弹「购买成功」→ app 毫无反应,**不报任何错**;点「恢复购买」→「没有找到可恢复的购买」。
2. 加上错误提示后,同一操作变成明确报错:**「购买已完成,但没有查到对应权益」** —— 这一条把问题锁死了。

### 两个独立缺陷

**缺陷一:所有失败路径都是静默的。**

```swift
case .success(let verification):
    if let transaction = try? Self.checkVerified(verification) { ... return true }
    return false          // ← lastError 没写,PaywallView 只在 lastError 非空时弹窗
```

`try?` 吞掉验签失败,`return false` 又不留话;`.pending`(Ask to Buy)同样静默。于是 Apple 自己的成功弹窗照常出现,app 什么都不做也什么都不说。**这正是最难排查的那种 bug:症状和「什么都没发生」一模一样。**

已修:验签失败、权益没到账、待确认、未知状态,四条路径各有各的话;`purchase()` / `restore()` 开头清掉上一次的 `lastError`,避免报一个早就过期的错。`refreshEntitlements` 单独统计**验签失败**的交易笔数 —— 以前「买到了但验不过」和「压根没买过」在界面上都是「没有找到可恢复的购买」。PaywallView 的恢复按钮现在优先显示具体错误,「没有找到可恢复的购买」只留给真的一笔都没有的情况。

**缺陷二(真正的元凶):购买成功后绕道 `currentEntitlements` 反推权益。**

```swift
let transaction = try Self.checkVerified(verification)
await transaction.finish()
await refreshEntitlements()        // ← 去查 Transaction.currentEntitlements
if !premium { /* 报错 */ }
```

`Transaction.currentEntitlements` 是**当前状态的快照**,在沙盒(以及弱网)下相对刚完成的购买有明显滞后。而 `product.purchase()` 返回、且验签通过的那笔 `transaction` 是**即时且权威**的凭据 —— 代码却把它 finish 掉扔了,转头去问一个还没刷新的缓存。查不到 → `premium` 保持 false → 功能不解锁。

已修:
- 新增 `grant(from:)`,拿已验签的 transaction **直接授予权益(只升不降)**,`finish()` 放在授予之后;
- `Transaction.updates` 监听同样改成直接授予;只有 `revocationDate != nil`(退款/撤销)才回去跑 `refreshEntitlements` 走降级;
- `refreshEntitlements` 仍负责启动/恢复时的校正(退款、过期、换设备),但加了**降级保护**:如果本地缓存说有权益、而 `currentEntitlements` 返回空,先等 2 秒重查一次再决定,免得沙盒抖动把刚付过钱的用户重新锁在门外。

### 附带修掉的:`Maren.storekit` 里 5 个 UUID 全是非法的

```
A1B2C3D4-0000-4000-8000-MAREN0000001     ← M / R / N 不是十六进制字符
A1B2C3D4-0000-4000-8000-LIFETIME0001
A1B2C3D4-0000-4000-8000-GROUP0000001
A1B2C3D4-0000-4000-8000-YEARLY000001
A1B2C3D4-0000-4000-8000-MONTHLY00001
```

这个文件是手写的(不是 Xcode 生成),`identifier` 和全部 `internalID` 都不是合法 UUID。已全部换成合法十六进制值,产品 ID 与价格一字未动。

> 这只影响 **Xcode 本地 StoreKit 测试环境**(Edit Scheme → Run → Options → StoreKit Configuration)。你这次是 Archive/TestFlight 上的真沙盒,走的不是这条路 —— 所以它不是本次的元凶,但留着早晚要踩。
